# Brownfield Workflow

Use this workflow when applying GSD to an existing repository.

## Sequence

1. Inspect repository structure.
2. Identify language, frameworks, build tools, tests, CI, deployment, and data stores.
3. Identify existing documentation.
4. Identify existing governance gaps.
5. Map major components.
6. Identify high-risk areas.
7. Create or update documentation policy.
8. Create or update project map.
9. Create implementation log.
10. Create resume marker.
11. Propose first safe tranche.
12. Do not change functional code until governance baseline exists.

## Required brownfield outputs

- `docs/BROWNFIELD_ASSESSMENT.md`
- `docs/PROJECT_MAP.md`
- `docs/RISK_REGISTER.md`
- `docs/RESUME_MARKER.md`
- `docs/IMPLEMENTATION_LOG.md`

## Brownfield rule

No code changes until the repository has been read, mapped, and assigned a safe resume point.
